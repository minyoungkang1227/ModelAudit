# ModelAudit

금융회사가 쓰는 AI 모델을 내부를 보지 않고 검증하는 도구다. 모델은 "표를 받아 점수를 돌려주는 함수"로만 다룬다.
외부에서 사 온 모델은 내부를 볼 수 없기 때문이다.

지금 되는 것은 모델 성능 유지, 강건성, 드리프트, 공정성, 설명가능성 점검과 검증 보고서다.
LLM 점검은 [Collatio](https://github.com/minyoungkang1227/collatio)가 하고, 여기서는 그 결과를 읽어 같은 틀의 보고서로 적는다.

## 결과 (2026-11-25, German Credit 1,000건, 30회 반복)

검증 도구가 문제를 잡는지 알려면 문제의 크기를 알아야 한다. 그래서 문제를 일부러 심고 잡은 횟수를 셌다.
칸은 잡은 횟수/시도다. 전체 표는 [docs/findings.md](docs/findings.md)에 있다.

| 심은 것 | 약하게 | 중간 | 세게 | 안 심었을 때 잘못 잡음 |
|---|---|---|---|---|
| 드리프트: 대출 금액이 1.1 / 1.3 / 1.6배 | 3/30 | 30/30 | 30/30 | 0/30 |
| 드리프트: 월세 거주 고객이 1.5 / 2.5 / 4배 자주 | 3/30 | 25/30 | 30/30 | 0/30 |
| 직접 차별: 25세 이하 점수를 0.05 / 0.10 / 0.20 깎음 (바꿔 넣기 점검) | 30/30 | 30/30 | 30/30 | 0/30 |
| 간접 차별: 25세 이하 우량 고객의 20 / 40 / 60%를 학습 정답에서 부실로 바꿈 (승인율 비) | 22/30 | 27/30 | 29/30 | 13/30 |

읽는 법은 세 가지다.

- 큰 드리프트와 직접 차별은 잡는다. 10% 안팎의 작은 변화는 이 표본 크기(기준 600, 새 표본 400)에서 거의 못 잡는다.
- **결과 지표만으로는 간접 차별을 가려내지 못한다.** 아무것도 심지 않은 모델도 30번 중 13번 걸린다. 이 자료에서 25세 이하의 실제 우량 비율이 낮아서(58% 대 73%) 승인율이 원래 갈리기 때문이다. 심은 차별과 자료에 원래 있던 차이를 결과만 보고는 나눌 수 없다.
- 새 표본이 100건이면 PSI 관행 기준(0.10)은 아무 변화가 없어도 95%에서 경고를 낸다. 우연으로 나올 크기인지 함께 보면 7%로 줄지만, 진짜 변화를 잡는 힘도 같이 떨어진다.

건수가 많은 Home Credit(약 30만 건)에서 두 가지 문제가 드러나 고쳤다.

- PSI 관행 기준은 큰 표본에서 반대로 틀린다. 금액 1.1배는 우연의 100배 크기인데도 통과로 나왔다. 우연 여부와 크기를 따로 보게 고친 뒤에는 8/8 잡는다.
- 간접 차별은 기준 모델과 나란히 놓으면 갈린다. 검증자가 같은 자료로 따로 세운 모델과 비교하자, Home Credit에서 간접 차별을 8/8 잡고 심지 않은 모델은 0/8 걸렸다. German Credit처럼 집단이 76명뿐이면 여전히 약하다(5~17/30, 대조 3/30).

강건성 점검도 같은 방식으로 쟀다. 금액이 1% 달라질 때 결과가 뒤집히도록 만든 모델을 두 자료에서 전부 잡았고(30/30, 8/8), 로지스틱 표본 모델은 한 번도 걸리지 않았다.
다만 아무것도 심지 않은 부스팅 모델이 Home Credit에서 '주의'로 걸린다(뒤집힘 3.2%). 나무 모델의 원래 성질이라 기준을 모델 종류에 따라 읽어야 한다.

설명가능성은 모델이 내놓는 거절 사유를 점검한다. 사유의 20%를 거짓으로 바꾼 경우를 두 자료에서 29/30, 8/8 잡았고 정직한 사유는 1/30, 0/8 걸렸다.
다만 주의 기준을 결과를 보고 80%에서 90%로 올린 뒤의 숫자다.

## 쓰는 법

```
pip install -e .
python scripts/fetch_german.py                      # UCI에서 자료를 받아 data/german.csv로 저장
python -m modelaudit report  --data data/german.csv   # 표본 모델 검증 보고서 -> runs/report.md
python -m modelaudit planted --data data/german.csv   # 문제를 심고 잡는지 세기 -> runs/planted.md
python scripts/prep_home_credit.py 받은폴더/application_train.csv
python -m modelaudit planted --data data/home_credit.csv --preset home-age --seeds 10
python -m modelaudit llm --collatio collatio.json     # Collatio 결과를 보고서로 -> runs/llm_report.md
pytest
```

`fetch_german.py`가 인증서 오류로 실패하면(2026-11-27에 UCI 사이트 인증서가 만료돼 있었다) UCI 사이트에서 `german.data`를 직접 받아 경로를 넣는다.

```
python scripts/fetch_german.py 받은_경로/german.data
```

두 스크립트는 자료 옆에 `<이름>.meta.json`(출처, 받은 날, 행 수, 원본·가공본 SHA-256)을 남긴다. 보고서는 이 기록을 읽어 해시를 다시 재고, 기록이 없거나 파일이 바뀌었으면 "읽을 때 주의"에 적는다. 어느 판본의 자료로 낸 보고서인지 나중에 증명하기 위해서다(BCBS 239 원칙 3·5).

## 구성

| 파일 | 하는 일 |
|---|---|
| `drift.py` | 변수별 PSI, 우연 여부 검정(카이제곱 근사), 여러 변수 보정(Holm) |
| `fairness.py` | 승인율 비, 기회 격차, 바꿔 넣기, 기준 모델 비교 |
| `samples.py` | 검증 대상 표본 모델, 심는 문제 |
| `planted.py` | 심고 세는 실험 |
| `robust.py` | 입력을 1% 바꿨을 때 승인·거절이 뒤집히는 비율 |
| `explain.py` | 거절 사유의 충실도와 일관성 |
| `llm.py` | Collatio 결과를 읽어 원칙·영역별 판정으로 바꿈 |
| `perf.py` | 새 표본에서 구별력(AUC)이 유지되는지 |
| `report.py` | 신뢰성 원칙 네 영역별 판정과 위험등급을 적은 보고서 |

## 보고서

보고서는 금융위 「금융분야 인공지능 가이드라인」의 신뢰성 원칙 네 영역(모델 성능 관리, 데이터 품질, 공정성·편향성, 설명가능성)별로 판정을 낸다.
대출 심사는 금감원 AI RMF에서 위험점수와 무관하게 고위험으로 분류되므로, 그 등급에 요구되는 통제도 함께 적는다.
검사하지 않은 영역은 통과로 치지 않고 따로 적는다. 위험점수 자체는 내지 않는다.
LLM 보고서는 같은 틀에 보안성 원칙(프롬프트 인젝션)이 더해진다.

두 문서의 원문은 구하지 못했고 보도자료와 해설을 근거로 했다. 확인한 것과 해석한 것의 구분은 [docs/mapping.md](docs/mapping.md)에 있다.
